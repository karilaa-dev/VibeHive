# WinForms

The application starts with the existing Events login and registration screen. After login, the main menu shows the signed-in account and all four service statuses, checked every five seconds. Log Out clears the session and returns to login. Every form opens in the center of the screen. The menu hides while a component form is open.

User displays use `Name (id)` for sessions, rental customers, booking owners, playlist owners, collaborators and invitation choices. Numeric IDs remain in API requests and models for identity checks.

`ExampleData.cs` contains the example-data loading function and response helper. The button handler in `MainForm.cs` calls `ExampleData.LoadAsync()` and keeps the once-per-GUI-run limit.

1. **Load Example Data** is Admin-only and can finish once per GUI run, including across logout/login. It keeps the five-album/two-rental setup and creates only regular users Alex Morgan and Jamie Lee. **VibeHive Community** belongs to Alex, includes ten sample songs, and invites every other regular user. Example rentals belong to the regular demo users. Existing data is kept; an interrupted load can be retried without duplicating the playlist, invitations or songs. The example accounts are `alex.morgan@example.com` and `jamie.lee@example.com`, both with password `Example@123`.
2. **Music Rental Management** opens **Active Rentals** first, followed by **Albums**. All roles can browse, rent and return albums. Album entry fields and Add/Delete buttons are enabled only for Admins. Admins choose any regular customer from a `Name (id)` dropdown loaded from Events; Refresh reloads customers and keeps the selection. Users and Event Managers rent for their own signed-in account. Users see and return their own rentals; admins can see and return all rentals.
3. **Album Inventory** is enabled on the main menu only for Admins. It adds, finds, updates, and deletes albums through gRPC, sending the session JWT for edits. Click Refresh to load changes made elsewhere. Errors use message boxes.
4. **Collaborative Playlist Builder** is available to regular Users and Admins. Event Managers cannot open it. Invitations list only regular users who are not the owner or already collaborators on the selected playlist. Invite is disabled when no eligible users remain or the playlist is private. Admin and Event Manager invitations are rejected by the API. Admins can view and manage all playlists without invitations; voting still requires ownership or collaboration. Songs use the original manual title, artist, genre and duration fields. Refresh List reloads users and playlists. Songs, invitations and rankings refresh every four seconds.
5. **Event Management and Ticketing** reuses the startup session for events and bookings. Bookings always belong to the JWT user. User and Event Manager accounts see their upcoming active tickets in **My Bookings**; Admins see everyone's upcoming active tickets in **All Bookings**, including owner IDs. **Past / Cancelled Bookings** keeps tickets for past events and all cancelled tickets, with the same user/Admin visibility. Refresh Bookings reloads both tabs. Owners can cancel their own bookings from either tab; Admins can cancel anyone's. A successful cancellation refreshes bookings and event availability. The Create Event tab is shown only for Admin and Event Manager accounts.

No users are seeded at startup. Register an Admin on the startup screen, sign in, and use Load Example Data to create the regular example accounts. Event Manager accounts must also be registered manually.

Start Music Rental and Album Inventory before loading examples or using their forms. `ClientSettings.cs` contains default client addresses. `VIBEHIVE_MUSIC_RENTAL_URL`, `VIBEHIVE_INVENTORY_URL`, `VIBEHIVE_PLAYLIST_URL`, and `VIBEHIVE_EVENTS_URL` can override them before launch.
